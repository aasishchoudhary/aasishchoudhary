# Client Trust Framework

## The goal
A client should not have to trust a claim blindly. They should be able to inspect enough evidence to form their own judgment.

## Trust signals
### Technical
- readable repositories
- clear architecture
- tests
- reproducible setup
- meaningful commits
- documented assumptions

### Professional
- clear scope
- explicit deliverables
- honest project status
- security awareness
- limitations stated openly
- no fabricated testimonials

### Communication
Explain work as:
**Problem → Approach → Result → Evidence → Limitation → Next step**

## Risk reversal
For uncertain work:
1. define the uncertainty
2. create a small experiment
3. measure it
4. decide whether to scale

## Rule
> Never make the client discover a limitation after deployment if it could have been documented before development.
